# 原生文本接入

## 内置原生组件适配器

匹配已核对的 IL2CPP WebAssembly 构建时，资源规则可以留空。先选择 Profile、授权实际页面及嵌入框架，然后刷新页面，让适配器在引擎初始化前接入。弹出菜单会显示「原生组件适配已就绪」。未知构建不会套用其他版本的内存地址。

适配器只在经过确认的字符串和组件函数入口读取文本，不进行整个堆的字符串扫描；译文通过原来的 TextMeshPro 或 UI.Text 赋值函数回写。托管 GC 句柄保护当前组件和原文，组件停用或销毁时释放。旧句、已销毁组件和旧 Profile 的异步结果不再回写。

多个界面文字同时出现时，翻译请求进入有界队列，不因页面桥暂时繁忙而直接丢弃后续段落。最多等待 512 个请求、同时发送 4 个翻译请求；页面桥总计最多 6 个在途请求，为设置、字体和诊断保留容量，实际翻译服务仍最多并发 2 个请求。当前对白优先于排队的界面文字；单次桥等待计时从实际发送开始。组件关闭、换文、暂停和配置变化会丢弃已经失效的等待任务。队列超限、服务错误和已发送请求超时仍回退到原文，不无限重试。

后台翻译仍在处理时，隔离桥每秒发送不含原文的进度事件，刷新页面的空闲等待计时。后台排队和分段翻译不会再被页面误判成接口超时；服务本身的单次请求仍使用设置的超时，整项页面任务另有 15 分钟硬上限。模型 API 接收完整段落和内部换行，免密钥服务才按字节拆分。已确认的显示文本保留 `|` 分隔符并翻译两侧文字；未分类的注音或控制语法仍保持原样。

剧情气泡在初始化时绑定完整句子；逐帧显示的短前缀不会另发翻译请求。异步译文到达时，通过原有渲染函数更新整句，并使用原生整句显示入口，避免再次播放逐字动画。初次显示原文仍保留原来的动画；返回相同文本时不重新初始化。下一句开始、组件关闭或 Profile 变化后，旧结果不再写入。

已显示译文的对白组件，在点击推进或逐字更新时重复写入当前原文或短前缀，会在原生赋值前沿用整句译文，避免先闪回原文或再次播放译文前缀。整句托管译文重复使用，换句、清空、恢复原文或销毁绑定时释放。新句和清空仍由原引擎正常处理，暂停或关闭剧情翻译时不拦截原文。

Naninovel RevealableText 在完整渲染字符串赋值时绑定对白，角色名提供历史参考中的说话人。异步译文只刷新文本渲染层，并按新字数恢复原来的显示进度；原始剧情、配音控制和历史记录保持由应用处理。脚本预读仅处理有界的普通文本行，跳过指令和表达式；已编译脚本仍在实际显示时翻译。

Utage 对话窗口的 TextData 可以包含同一页尚未点击到的后续句子。适配器核对当前原生指令、已开放的字数边界与原生解析结果，只绑定当前完整句子，分别处理正文和姓名。中文显示字数按当前原生进度换算；点击完成本句、继续下一句和同页累积文字保持由引擎控制，不强制整页可见。译文抵达时保留当前进度，已经完成的句子不会再从头播放。无法验证边界时保留原来的文字与遮罩。另一类逐字消息组件从当前消息对象读取完整对白，在原生帧更新期间关联实际 UI.Text；逐帧短前缀不产生新的翻译请求，已显示的译文不会再次逐字播放。帧时间参数按原来的浮点类型传递。

原生 novel 渲染器使用负数可见字数表示全部显示。适配器保留这个标记，不将其换算成零字；译文缓冲只包含已推进的指令，因此全部显示也不会提前展示下一句。运行诊断同时提供原生与译文的可见字数，不包含原文或译文。

导出函数名经过压缩的构建也按完整 SHA-256 指纹选择映射，保留框架使用的原导出名。映射缺失、类型不符或适配失败时，使用未经修改的模块。当前新增的两个构建已通过实际 WASM 重写及编译校验、字符串和生命周期回归测试；这些检查仍不等价于客户端中的画面和玩法验证。

界面适配还覆盖已核对构建的旧版 `UnityEngine.UI.Text`、TextMeshPro 的公共文字处理入口，以及场景中的二维与世界空间 TextMeshPro 生命周期。后者可以读取直接 `SetText`、格式化数值、StringBuilder 和字符数组生成的完整文本。已接入字体加载入口的旧版 UI.Text 优先使用能够显示译文的原字体；缺字时使用扩展自带的原生备用字体。针对构造函数未加载动态字形的已核对构建，适配器通过 Unity 自己的分配器将字体字节放入新建备用字体的数据区，再调用对应的原生初始化入口，不修改应用原字体。只有完整构建指纹匹配、字体数据检查和探测字形都成功时才应用。旧版 TextMeshPro 可从该 Font 创建动态字体。失败时保留原字体；字号、样式与颜色保持原组件的设置，两类组件不会混用字体函数。指纹前缀 `62bd9e5b` 的新增旧版 Text 路径只保留原字体，独立中文备用字体尚未接入；该构建的 TMP 备用字体不受影响。实际字形和排版仍需在客户端确认。

已核对的旧版 UI.Text 构建还在 `OnPopulateMesh` 检查完整组件字符串，补上直接修改文字字段或自定义赋值函数绕过 `set_text` 的路径。原始绘制函数仍按原参数调用一次，译文通过已有原生 setter 更新后续画面，不在 mesh 回调中重放剧情。已适配的 TMP 构建统一覆盖 `PopulateTextProcessingArray`。纯汉字菜单可以进入翻译；已写回的译文保留来源关联，组件重新启用时不会把自己的输出作为新原文。来源不明确的重复译文保留当前显示。

三份 TMP 构建还在 `TextMeshProUGUI.OnPreRenderCanvas` 与 `TextMeshPro.OnPreRenderObject` 复查当前文字，补充绘制阶段的直接字段更新。已翻译的整句保护在原始绘制前执行；普通 UI 在原始绘制后捕获，保留原参数、返回值与调用次数。世界空间组件同样在停用与销毁时取消任务和释放托管根。

捕获仍有边界：每条输入最多 2000 个 UTF-16 码元，最多同时保留 256 个原生文字绑定；数值和未识别为源语言的内容不提交。超限或不可读的新文字会释放同组件旧绑定，避免旧译文覆盖新内容。运行诊断的 `nativeCapture` 和控制台 `coverage=` 提供已观察次数、活动绑定数、语言 / 长度 / 容量 / 不可读跳过计数；这些是已接入入口的统计，无法证明未接入的组件没有遗漏，也不代表画面文字总数。

「共用翻译与语言设置 → 提前翻译」默认 2 句，范围 0–20，0 为仅翻译当前对白。剧情脚本预读需要已匹配的读取入口：普通文本 / CSV 适配器仅预读每次载入时的开头几句；已核对的编译消息脚本适配器在原生预载遍历期间，用原来的只读字符串函数取得对白与角色名，并以命令偏移关联实际播放位置。它不额外推进命令栈，不提前执行剧情、配音、分支或历史记录。最多采集 4096 条、合计一百万字符；动态或无法读取的参数留待显示时处理。

编译消息脚本按实际位置向后保持设定的句数窗口，每次只提交一条背景对白，姓名随对白准备。重复帧不会把窗口扩展到整章。暂停、关闭剧情翻译或设置 0 时停止后续调度；切换 Profile、翻译配置或场景时拒绝旧结果。准备好的整句通过原有组件赋值，显示时不重复请求。普通脚本、其他编译格式、分支跳转和动态对白的覆盖仍需分别核对，不承诺所有 Unity 构建都支持预翻译。

预读使用请求当时已经显示的历史，不将未来对白加入参考；准备好的译文实际绑定显示后才记入历史。显示顺序仍以原生文字绑定为准。预翻译会使用所选在线服务及其提交预算；资源包、目录和网络校验值保持原样。尚未匹配的 Unity 版本、其他文字组件和图片文字仍需要适配。

已核对的原生 novel 页还可从引擎现有的对白指令列表准备后续完整句子，仍受提前翻译句数限制。预读不会把整页译文写到当前组件，也不执行下一条指令。切换 Profile 或翻译配置后，旧上下文的同页译文前缀会被清除；已结束页与无法枚举的脚本仍使用当前文字接入。

部分已核对构建的原字体通过字符覆盖检测，画面仍会漏字。此类构建的中文译文优先使用扩展自带字体，不再仅依据覆盖检测保留原字体；纯英文且原字体覆盖完整时仍保留原字体。动态字体使用对应的构造入口创建材质和纹理，并检查渲染材质后再应用，避免只加载字形却显示空白。已核对的自定义渲染器使用带显式字号的动态字体构造入口，避免路径构造留下不可用的字体度量；原组件的字号不变。加载字体数据后，通过原生入口重新计算已缓存的基线和行高，并拒绝异常行高，避免多行重叠。这个选择只随对应构建指纹生效，暂停和释放绑定时仍恢复原字体。

内置组件适配器随扩展加载 OFL 1.1 许可的中文字体，不联网下载。字体只写入当前引擎的内存文件系统，使用原生 TextMeshPro 动态图集渲染译文；暂停、恢复原文或释放绑定时恢复原字体。覆盖基本多文种平面内的 30,445 个字符；字形覆盖和实际排版仍需要按画面验证。其他接入路径不自动替换字体。详见[字体来源和许可](../extension/fonts/README.md)。

WebAssembly 适配的自动测试覆盖函数分派、原函数保留、指纹不匹配回退、UTF-16 字符串、GC 句柄释放和过期结果；不能代替实际游戏的显示及玩法验证。

## JSON 资源

先在浏览器开发者工具确认文本资源的实际 URL、编码和字段。规则只是解析声明，不是要执行的代码；不支持自定义 JavaScript。

```json
[
  {
    "url": "/StreamingAssets/story/*.json",
    "fields": [
      { "path": "lines[*].text", "kind": "story", "speaker": "speaker" },
      { "path": "lines[*].speaker", "kind": "name" },
      { "path": "choices[*].label", "kind": "story" }
    ]
  },
  {
    "url": "https://assets.example.test/localization/menu.json",
    "fields": [{ "path": "labels[*].text", "kind": "ui" }]
  }
]
```

- `url` 为当前框架域名下的绝对路径，或固定 HTTP(S) 域名的完整 URL；`*` 匹配路径。不匹配查询参数和片段，规则不得包含凭据。
- `path` 支持对象键、数组下标和 `[*]`。例如 `chapters[0].lines[*].text`。不递归改写所有字符串。
- `kind` 只能为 `story`、`name` 或 `ui`。姓名随剧情开关，界面字段随界面开关。
- `speaker` 可选，表示与文本同一对象中的姓名字段，为模型提供当前说话人。载入文件的先后顺序不能证明对白已播放，因此 JSON 预载不会产生历史参考。

仅支持成功 GET 的 UTF-8 JSON 响应。异步 XHR 支持 text / json / arraybuffer；同步 XHR、POST、部分响应、图片、二进制包和 WASM 不改写。匹配 XHR 的完成事件会在翻译完成后异步重发；应用若要求可信原生事件，应使用文本桥或其他适配。未匹配请求保持原生事件流程。

每个资源最多 1 MiB、10000 个 JSON 节点、64 层、32 条文本；每条最多 2000 字符，最多 20 条规则。超过限制时整个资源使用原文，缩小字段范围后重试。资源拦截最多等待 15 秒；超时、无权限、接口失败、暂停或配置变化均回退。后台已完成的译文可被后续请求复用。

原始字符串 token 是替换范围，其他 JSON 字节保持不变。不会通过 `JSON.stringify` 整个原资源，从而保留大整数 ID、小数精度表示、重复键、控制命令和空白。XHR 的 `responseType = json` 本来就由浏览器解析成对象，其数字语义仍遵循浏览器 JSON 解析规则。

保存规则后刷新页面。首次授权后的临时注入无法改写已经读入 Unity 的数据，也无法拦截之前保存的原始网络函数。已经通过响应读取的文本无法通用地追踪回 Unity 组件，暂停或切换 Profile 后刷新才能全面更新这部分文字。

## Unity 文本桥

这条路径用于自己能修改的 Unity 项目，不能直接给已编译的第三方成品补上 C# 方法。

1. 把 [UnityWebTranslator.jslib](../examples/unity/UnityWebTranslator.jslib) 放到 `Assets/Plugins/WebGL/`。
2. 把 [UnityWebTextBridge.cs](../examples/unity/UnityWebTextBridge.cs) 加入 Unity 项目。
3. 创建一个唯一命名的 GameObject，添加 `UnityWebTextBridge`。名称应在 80 字符以内，每个组件使用不同的 GameObject 名称。
4. 在 `onText` 事件中连接实际 UI.Text / TextMeshPro 组件的 text 属性，或自己的文本赋值方法。
5. 将原本的 `label.text = dialogue` 改为 `bridge.ShowDialogue(dialogue, speaker)`。设置 `kind` 区分剧情、姓名或菜单。
6. 切换剧情时设置组件的 `sceneId`。目标字体与换行布局由游戏自己处理。

未安装扩展时先显示原文；翻译失败也保留原文。结果通过 `Module.SendMessage` 调用本项目组件的 `OnTranslation`，组件校验请求 ID，避免旧句覆盖新句。异步任务不持有 WASM 堆指针、不扫描或改写托管内存。

只要页面已经授权并绑定 Profile，也可从已有的 JavaScript 文本接口使用：

```js
// Your native text setter, supplied by your application.
const release = window.UnityWebTranslator.bind(
  'dialogue-slot',
  originalText,
  text => gameTextApi.setText(text),
  { kind: 'story', speaker: speakerName, scene: sceneId }
);
// Dispose when this native text slot is no longer active.
release();
```

`bind` 只在仍有效的当前文字真正回写后记录历史。最多保留设置的最近句数，不持久保存；场景、Profile、目标语言、翻译服务变化和关闭参考时清空。最多 256 个绑定。暂停时恢复原文，恢复翻译时重译当前绑定。

`translate(text, options)` 返回译文 Promise。对于由应用自己赋值的接口，只有确认会显示该句时才使用 `recordHistory: true`；默认不自动记录。`resetHistory()` 可主动清除场景参考。

官方接口依据：[Unity 浏览器脚本交互](https://docs.unity3d.com/Manual/webgl-interactingwithbrowserscripting.html)、[JavaScript 插件](https://docs.unity3d.com/Manual/web-interacting-browser-js.html)、[SendMessage](https://docs.unity3d.com/Manual/web-interacting-browser-unity-to-js.html)。本项目不认为 `SendMessage` 能读取任意编译后的 Text 组件。

## 诊断与验证边界

弹出菜单显示各授权框架上报的计数与最近资源路径。诊断仅存在扩展后台内存，最多 128 个框架，2 分钟过期；不记录资源查询参数、密钥或对白全文。页面本身可以伪造自己的状态，诊断不构成受信的引擎证明。

原生 novel 诊断额外记录成功识别的当前指令次数、未能验证边界的次数，以及最近指令的起止字数与整页字数，不记录正文、姓名或托管地址。它用于区分接入失败与显示问题，不能证明整款应用的覆盖率。

仓库测试验证 JSON/XHR/文本桥协议与真实后台和缓存之间的调用流程。尚未提供已编译的 Unity 示例构建，C# 需自行在 Unity 编辑器内编译。成功跑通协议不能证明某一第三方应用已经适配。
